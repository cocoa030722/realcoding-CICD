■ 프로젝트명
  Spring PetClinic — 동물병원 관리 웹 애플리케이션

■ 개요
  Spring PetClinic은 Spring Framework의 공식 샘플 프로젝트로,
  동물병원의 수의사, 반려동물, 보호자, 방문 기록을 관리하는
  웹 애플리케이션입니다. Spring Boot 기반으로 구현되어 있으며
  실제 엔터프라이즈 애플리케이션 개발 패턴을 학습하는 데
  활용됩니다.

■ 주요 기능
  - 반려동물 보호자(Owner) 등록 / 조회 / 수정
  - 반려동물(Pet) 등록 및 종류(Type) 관리
  - 수의사(Vet) 목록 및 전문 분야 조회
  - 방문 기록(Visit) 등록 및 미래 날짜 유효성 검사
  - 입력값 유효성 검증 (이름 길이 등 Bean Validation 적용)

■ 기술 스택
  - 언어: Java 17
  - 프레임워크: Spring Boot, Spring MVC, Spring Data JPA
  - 템플릿 엔진: Thymeleaf
  - 빌드 도구: Maven (mvnw), Gradle (gradlew)
  - 데이터베이스: H2(기본/인메모리), MySQL, PostgreSQL
  - 컨테이너: Docker, Kubernetes
  - CI/CD: GitHub Actions

2. 적용된 CI/CD 기술
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 도구: GitHub Actions
  - 코드 저장소(GitHub)와 통합된 자동화 파이프라인 도구
  - .github/workflows/ 폴더의 YAML 파일로 파이프라인 정의

─────────────────────────────────────────────────────────────
[워크플로 1] CI — Java CI with Maven
  파일: .github/workflows/maven-build.yml
  트리거: main 브랜치 push 또는 pull_request
  실행 환경: ubuntu-latest / JDK 17 (AdoptOpenJDK)

  단계:
    1. 소스코드 체크아웃 (actions/checkout@v4)
    2. JDK 17 설치 및 Maven 의존성 캐시 복원
    3. ./mvnw -B verify 실행
       → 컴파일 → 단위 테스트 → 통합 테스트 → JAR 패키징
    4. 실패 시 워크플로 중단 → PR 머지 불가

  핵심 기술:
    - Maven Wrapper(mvnw): JDK 버전 고정 및 일관된 빌드 보장
    - 의존성 캐싱: 빌드 시간 단축 (cache: maven)
    - -B 플래그: 비대화형(batch) 모드로 CI 환경에 최적화

─────────────────────────────────────────────────────────────
[워크플로 2] CI — Java CI with Gradle
  파일: .github/workflows/gradle-build.yml
  트리거: main 브랜치 push 또는 pull_request
  실행 환경: ubuntu-latest / JDK 17

  단계:
    1. 소스코드 체크아웃
    2. JDK 17 설치
    3. Gradle 환경 설정 (gradle/actions/setup-gradle@v4)
    4. ./gradlew build 실행
       → 컴파일 → 테스트 → JAR 빌드

  핵심 기술:
    - Gradle Wrapper(gradlew): 버전 고정된 Gradle 실행
    - Maven과 동일한 소스를 두 빌드 도구로 검증

─────────────────────────────────────────────────────────────
[워크플로 3] CD — Deploy and Test Cluster (Kubernetes)
  파일: .github/workflows/deploy-and-test-cluster.yml
  트리거: main 브랜치의 k8s/ 폴더 변경 시 (push/pull_request)

  단계:
    1. 소스코드 체크아웃
    2. Kind(Kubernetes in Docker) 클러스터 생성
       → 로컬 K8s 환경을 GitHub Actions Runner 위에 구성
    3. kubectl apply -f k8s/
       → k8s/db.yml: PostgreSQL Secret + Service + Deployment
       → k8s/petclinic.yml: 앱 Deployment + NodePort Service
    4. Pod 준비 상태 대기
       → demo-db Pod: 최대 180초 대기
       → petclinic Pod: 최대 180초 대기

  핵심 기술:
    - Kind (Kubernetes in Docker): CI 환경에서 실제 K8s 클러스터 시뮬레이션
    - kubectl: K8s 리소스 선언적 배포 (apply)
    - Service Binding: Secret을 볼륨으로 마운트해 DB 접속 정보 주입
    - Health Probe: livenessProbe / readinessProbe로 Pod 상태 자동 확인

─────────────────────────────────────────────────────────────
[컨테이너 빌드 기술]
  - Spring Boot Buildpacks (Dockerfile 없이 이미지 생성)
    명령: ./mvnw spring-boot:build-image
  - Docker Compose: 로컬 MySQL/PostgreSQL 환경 구성
    파일: docker-compose.yml

[Kubernetes 매니페스트 구성]
  k8s/db.yml
    - Secret: DB 접속 정보 (host, port, user, password, database)
    - Service: 클러스터 내부 PostgreSQL 접근 엔드포인트
    - Deployment: PostgreSQL 컨테이너 (postgres:18.3)

  k8s/petclinic.yml
    - Service: NodePort 80→8080 외부 노출
    - Deployment: 앱 컨테이너, postgres 프로파일 활성화
      환경변수: SPRING_PROFILES_ACTIVE=postgres
                SERVICE_BINDING_ROOT=/bindings
